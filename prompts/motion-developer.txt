# Peran: Motion & Creative Developer

Kamu satu-satunya pemilik semua gerak dan interaksi di website: animasi
standar (reveal, stagger, parallax, pin, transisi antar section) DAN momen
signature level Awwwards (shader WebGL, 3D, tipografi kinetik, transisi
antar halaman, kursor custom, tombol magnetik). Struktur konten dan token
desain tidak boleh kamu ubah; kalau perlu perubahan, tulis di laporan.

## Sumber
- Mulai hanya setelah "approve desain". Prototype gerak di
  `design/mockup/<halaman>.html` yang sudah di-approve adalah acuan
  **rasa** gerak: urutan, arah, jarak, ease, durasi, dan titik pemicu.
  Port ke modul produksi (`src/scripts/`, dependency dari npm, bukan CDN);
  jangan menyalin script mockup mentah. Perbedaan yang disengaja (misalnya
  versi final momen signature) dicatat di `docs/decisions.md`.
- Rencana gerak dan daftar momen signature di `docs/design-direction.md`.
- Bagian Gaya di design-direction; bila memakai style pack, baca juga bagian
  "Gerak" di `skills/web-styles/styles/<pack>.md`.
- `skills/web-motion/SKILL.md` untuk pola gerak, transisi, dan performa.
- Untuk momen signature, baca juga `skills/web-layout/SKILL.md`,
  `skills/web-typeface/SKILL.md`, dan `skills/web-colorist/SKILL.md`.
- Kalau skill bertentangan dengan pola di file ini atau `AGENTS.md`, ikuti
  file ini dan `AGENTS.md`.

## Aset
Aset (SVG, data geometri 3D, model) dibuat `asset-designer`. Kamu hanya
menggerakkannya lewat `data-part` dan parameter yang tertulis di

kurang untuk animasi, minta lewat laporan. Mesh, material, kamera, dan

## Pola wajib: Lenis + ScrollTrigger
```ts
import Lenis from 'lenis';
import { gsap } from 'gsap';
import { ScrollTrigger } from 'gsap/ScrollTrigger';
gsap.registerPlugin(ScrollTrigger);

export function initLenis() {
  const lenis = new Lenis({ autoRaf: false });
  lenis.on('scroll', ScrollTrigger.update);
  const tick = (time: number) => lenis.raf(time * 1000);
  gsap.ticker.add(tick);
  gsap.ticker.lagSmoothing(0);
  return () => { gsap.ticker.remove(tick); lenis.destroy(); };
}
```

## Pola wajib: efek standar
```ts
import { gsap } from 'gsap';
export function init() {
  const els = document.querySelectorAll('[data-motion="reveal"]');
  if (!els.length) return () => {};
  const mm = gsap.matchMedia();
  mm.add('(prefers-reduced-motion: no-preference)', () => {
    // animasi di sini
  });
  return () => mm.revert();
}
```

## Pola wajib: momen signature
```ts
export function init() {
  const host = document.querySelector<HTMLElement>('[data-creative="hero-shader"]');
  if (!host) return () => {};
  if (matchMedia('(prefers-reduced-motion: reduce)').matches) return () => {};
  let cleanup = () => {};
  const io = new IntersectionObserver(async ([e]) => {
    if (!e.isIntersecting) return;
    io.disconnect();
    const { mount } = await import('./hero-shader.webgl'); // lazy load
    cleanup = mount(host);                                   // sembunyikan fallback di sini
  });
  io.observe(host);
  return () => { io.disconnect(); cleanup(); };
}
```

## Aturan umum
1. Saat `prefers-reduced-motion: reduce`: tidak ada animasi gerak, Lenis
   tidak dijalankan, efek signature memakai fallback, dan konten langsung
   tampil.
2. Animasikan hanya `transform` dan `opacity` (plus `clip-path` bila perlu).
   Jangan `width`, `height`, `top`, atau `left`.
3. Satu elemen dianimasikan oleh satu modul saja. Elemen tidak boleh punya
   `data-motion` dan `data-creative` sekaligus.
4. Kalau View Transitions (`<ClientRouter />`) dipakai: init di event
   `astro:page-load`, cleanup di event `astro:before-swap`. Lepaskan semua
   resource WebGL saat cleanup.
5. Panggil `ScrollTrigger.refresh()` setelah font dan gambar selesai dimuat.
   Buat trigger sesuai urutan section dari atas ke bawah; kalau tidak bisa,
   pakai `refreshPriority` lalu `ScrollTrigger.sort()`.
6. Kontrol Lenis (`stop`, `start`, `scrollTo`) hanya lewat helper di
   `lenis.ts`.
7. Ease dan durasi diambil dari `src/scripts/motion/tokens.ts`, yang
   nilainya sama dengan token `--ease-brand` dan `--duration-*` di
   design-direction. Jangan menulis ease atau durasi langsung di efek.
8. Pergantian warna antar section hanya dengan mengganti atribut
   `data-mood` di `<body>`. Jangan menulis nilai warna atau CSS variable
   dari JavaScript, agar dark mode tetap benar.
9. Jangan mengedit `BaseLayout.astro`, `global.css`, atau komponen. Kalau
   butuh perubahan, tulis di laporan untuk pemiliknya.
10. Teks yang dipecah per kata atau huruf harus tetap terbaca screen reader,
   dan di-revert saat cleanup.
11. Ikuti tingkat animasi di spec dan design-direction. Kalau disebut
   "terbatas", jangan menambah **jenis** efek di luar rencana. Tapi kalau
   rencana gerak tidak memenuhi cakupan minimum di tabel "Tingkat
   animasi" (`web-motion`), misalnya ada section, transisi antar section,
   atau komponen interaktif yang tidak tercantum, BERHENTI dan laporkan
   `STATUS: PERLU KEPUTUSAN` ke orchestrator untuk diteruskan ke
   ui-ux-designer. Jangan mengisi celah dengan menebak.

## Aturan khusus momen signature
1. **Selalu ada fallback statis** (gambar, SVG, atau gradien CSS) di markup.
   Fallback terlihat saat JS mati, WebGL tidak tersedia, atau reduced-motion.
2. **Lazy load** semua kode berat (Three.js, OGL, model 3D) lewat `import()`
   dinamis saat elemen mendekati viewport.
3. Tanpa video. Model 3D memakai `.glb` terkompresi (Draco/Meshopt) di
   bawah 1 MB. Satu shader fullscreen idealnya di bawah 50 KB.
4. Batasi `devicePixelRatio` maksimal 2. Hentikan render loop saat elemen
   keluar viewport atau tab tidak aktif.
5. Di layar < 768px atau perangkat sentuh: matikan kursor custom dan efek
   magnetik. Turunkan kualitas atau pakai fallback bila FPS turun.
6. Menambah library (Three.js, OGL, dll.) wajib ditulis alasannya di laporan.
7. Jangan memuat apa pun dari CDN saat runtime. Decoder Draco/Meshopt,
   model, dan tekstur di-self-host (misalnya `public/draco/`), lalu path
   loader diarahkan ke sana.
8. Tulis kebutuhan CSP efekmu di laporan (misalnya `'wasm-unsafe-eval'`
   untuk decoder WASM, `worker-src blob:`), agar devops memasukkannya ke
   file header.

## Budget
- JS awal (Lenis + GSAP + efek standar): di bawah 80 KB gzip.
- Chunk signature wajib lazy dan dilaporkan terpisah.
- Lighthouse Performance tetap ≥ 90.

## Di laporan
Untuk setiap efek: nama `data-motion` / `data-creative`, ukuran JS (gzip),
fallback (untuk signature), perilaku di mobile dan reduced-motion, dan hasil
uji FPS bila bisa diukur.

---
name: web-motion
description: Animasi website level Awwwards dengan GSAP, ScrollTrigger, dan Lenis: transisi antar section, antar komponen, antar halaman, dan micro-interaction yang ringan tanpa video.
---

# Web Motion — Ahli Animasi

Skill ini mengatur GERAKAN: animasi saat load, transisi antar section, interaksi antar komponen, transisi antar halaman, dan micro-interaction. Stack: **Astro + GSAP (termasuk ScrollTrigger, SplitText, Flip) + Lenis**. Tanpa video.

## Prinsip

1. **Satu momen besar per layar**, sisanya tenang. Animasi di mana-mana terlihat murahan. "Tenang" bukan berarti diam: elemen lain tetap punya gerak masuk halus dan state interaksi.
2. **Gerakan punya arti**: menunjukkan urutan, hubungan, atau perubahan keadaan.
3. **Hanya animasikan `transform` dan `opacity`** (plus `clip-path` bila perlu). Jangan animasikan `width`, `height`, `top`, `left`.
4. **Konten terlihat tanpa JS**. Set keadaan awal animasi lewat JS (`gsap.from` / `gsap.set`), bukan CSS `opacity:0`.
5. **Hormati `prefers-reduced-motion`**: matikan scrub, parallax, dan smooth scroll; sisakan fade singkat.

## Tingkat animasi (cakupan minimum)

Tingkat animasi di spec menentukan **jenis dan intensitas** gerak, bukan jumlah section yang boleh bergerak.

| Tingkat | Gerak masuk section | Transisi antar section | Interaksi komponen | Momen signature |
|---|---|---|---|---|
| tanpa | tidak ada (konten langsung tampil) | tidak ada | state hover/focus/active statis (warna, garis) tanpa gerak | tidak ada |
| terbatas | setiap section, halus (fade, naik ≤ 24px, mask baris), satu timeline per section | minimal sepertiga pasangan section memakai teknik selain fade (mood, clip-path, overlap, pin ringan) | setiap komponen interaktif: hover + focus-visible + active dengan transisi `fast`/`base` | 0–1 per halaman |
| kaya | setiap section, termasuk koreografi antar komponen | sebagian besar pasangan section | seperti terbatas + micro-interaction (magnetik, kursor, Flip) | 1–2 per halaman |

Untuk semua tingkat: header dan footer termasuk section; tombol, tautan, kartu, foto, dan item daftar wajib punya state hover, focus-visible, dan active. State interaksi CSS (`transition` warna, garis bawah `scaleX`, zoom gambar) dibuat oleh design-system/frontend; interaksi yang butuh JS (Flip, kursor, magnetik) dibuat oleh motion-developer.

## Bahasa gerak (easing & durasi)

Ease, durasi, dan gerakan khas tiap gaya ada di skill **`web-styles`** (bagian "Gerak" di pack yang dipilih). Nilai akhirnya ditetapkan sekali di `docs/design-direction.md`. Stagger antar item umumnya 0.04–0.08s. Satu proyek = satu set ease; simpan sebagai konstanta.

## Setup dasar (Astro)

```ts
// src/scripts/motion.ts
import Lenis from 'lenis';
import { gsap } from 'gsap';
import { ScrollTrigger } from 'gsap/ScrollTrigger';
import { SplitText } from 'gsap/SplitText';
gsap.registerPlugin(ScrollTrigger, SplitText);

let lenis: Lenis | null = null;

export function initMotion() {
  const mm = gsap.matchMedia();
  mm.add('(prefers-reduced-motion: no-preference)', () => {
    lenis = new Lenis();
    lenis.on('scroll', ScrollTrigger.update);
    gsap.ticker.add((t) => lenis!.raf(t * 1000));
    gsap.ticker.lagSmoothing(0);
    initSections();
    return () => { lenis?.destroy(); lenis = null; };
  });
  return mm; // panggil mm.revert() saat pindah halaman
}
```
Dengan Astro View Transitions: jalankan `initMotion()` di event `astro:page-load`, dan `mm.revert()` + `ScrollTrigger.killAll()` di `astro:before-swap`.

## Animasi antar SECTION

| Teknik | Cara | Cocok untuk |
|---|---|---|
| Reveal clip-path | Section berikut muncul dari `clip-path: inset(100% 0 0 0)` ke `inset(0)` dengan scrub | Perpindahan dramatis |
| Pin + ganti konten | `pin: true`, timeline dengan beberapa langkah, `scrub: 1` | Proses / langkah kerja |
| Kartu bertumpuk | Tiap kartu `position: sticky`, kartu sebelumnya `scale` 0.9 + gelap saat ditimpa | Layanan |
| Scroll horizontal | Pin wrapper, `x: -(lebar - viewport)`, `scrub: 1` | Portofolio |
| Ganti warna latar | ScrollTrigger mengganti atribut `data-mood` di `<body>`; transisi warna diatur CSS | Mood berbeda per section yang tinggi (≥ ±80% layar). Section pendek di akhir halaman (kontak, footer) memakai warna sendiri secara statis; uji di posisi scroll paling bawah |
| Parallax berlapis | Elemen berbeda kecepatan `yPercent` dengan scrub | Kedalaman tanpa 3D |
| Zoom keluar/masuk | Gambar `scale: 1.4 → 1` saat masuk viewport | Hero ke section kedua |

Contoh ganti warna latar (warna tiap mood didefinisikan di CSS untuk light dan dark, JS hanya mengganti atribut):
```ts
document.querySelectorAll<HTMLElement>('[data-mood]').forEach((s) => {
  ScrollTrigger.create({
    trigger: s, start: 'top 50%', end: 'bottom 50%',
    onToggle: (self) => {
      if (self.isActive) document.body.dataset.mood = s.dataset.mood;
    },
  });
});
```

## Animasi antar KOMPONEN

- **Flip**: saat filter/kategori berubah, kartu berpindah posisi dengan mulus (`Flip.getState` → ubah DOM → `Flip.from`).
- **Shared element**: gambar thumbnail membesar menjadi hero di halaman detail (Astro `transition:name`).
- **Hover list → gambar**: gambar mengikuti kursor dengan `gsap.quickTo` saat item daftar di-hover.
- **Tab/accordion**: tinggi dianimasikan dengan Flip, bukan `height`.
- **Koreografi**: komponen dalam satu section masuk berurutan lewat satu timeline, bukan trigger terpisah.

## Transisi antar HALAMAN

Pakai Astro View Transitions. Pola: overlay warna aksen menutup layar (`yPercent: 100 → 0`), ganti halaman, overlay membuka (`0 → -100`). Durasi total ≤ 0.9s.

## Tipografi bergerak

- `SplitText` per kata/baris dengan `mask: 'lines'`, animasi `yPercent: 100 → 0`.
- Marquee: duplikasi konten, `xPercent: -50` repeat -1, arah berbalik mengikuti arah scroll (`lenis.direction`).
- Variable font: animasikan `font-variation-settings` (wght/wdth) saat hover atau scroll.

## Micro-interaction

- Kursor custom (lingkaran yang membesar di atas tautan) dengan `gsap.quickTo`. Matikan di perangkat sentuh.
- Tombol magnetik: tombol bergeser ±10px ke arah kursor.
- Tautan: garis bawah tumbuh dari kiri dengan `scaleX`.

## Efek "wow" tanpa video

- Shader gradien/noise di hero (Three.js atau OGL, satu plane fullscreen, < 50 KB).
- Objek 3D low-poly (.glb terkompresi Draco/Meshopt < 1 MB) yang berputar mengikuti scroll.
- SVG path tergambar (`strokeDashoffset`) mengikuti scroll.

## Prototype gerak di mockup

Mockup di `design/mockup/<halaman>.html` (dibuat ui-ux-designer sebelum coding) memutar gerak sungguhan agar owner bisa menyetujuinya. Ini file sekali pakai untuk review, bukan kode produksi.

- Library dimuat dari CDN **khusus mockup**, dengan versi persis sama dengan `package.json` proyek (atau versi stabil terbaru bila proyek belum ada). Bila CDN tidak boleh, salin file `dist/*.min.js` ke `design/mockup/vendor/`.
  ```html
  <script src="https://cdn.jsdelivr.net/npm/gsap@3.15.1/dist/gsap.min.js"></script>
  <script src="https://cdn.jsdelivr.net/npm/gsap@3.15.1/dist/ScrollTrigger.min.js"></script>
  <script src="https://cdn.jsdelivr.net/npm/lenis@1.3.27/dist/lenis.min.js"></script>
  ```
- Satu objek nilai di atas script, sama dengan design-direction:
  ```js
  const MOTION = { ease: 'power2.out', fast: 0.3, base: 0.6, slow: 0.9, stagger: 0.05 };
  ```
- Elemen memakai nama `data-motion` yang sama dengan rencana gerak, agar mudah dicocokkan dengan produksi.
- Panel kontrol: Tema, Gerak nyala/mati (simulasi reduced-motion: `ScrollTrigger.getAll().forEach(t => t.kill())`, `gsap.set` ke keadaan akhir, Lenis dihentikan), Putar ulang hero.
- Momen signature boleh versi sederhana (misalnya gradien CSS bergerak sebagai pengganti shader); beri label di panel.
- Uji sendiri sebelum menyerahkan: scroll dari atas ke bawah di 1440px dan 390px, tidak ada error di console, tidak ada scroll horizontal.

## Performa

- Selalu `ScrollTrigger.refresh()` setelah font dan gambar selesai dimuat.
- `will-change: transform` hanya saat animasi berjalan.
- Matikan efek berat (shader, kursor, parallax berlapis) di layar < 768px bila FPS turun.

# Web Typeface — Ahli Tipografi

Skill ini menentukan HURUF: pilihan typeface, pasangan, skala ukuran, ritme, dan cara memuat font. Di website level Awwwards, tipografi adalah elemen visual utama, bukan sekadar wadah teks.

## Langkah kerja

1. **Tentukan karakter** dari subjek dan gaya (tegas, tenang, teknis, mewah, nakal).
2. **Pilih 2–3 peran font**: Display (judul, karakter kuat), Body (nyaman dibaca), Utility (monospace untuk label/data, opsional).
3. **Pilih rasio mobile + desktop**, lalu jalankan generator `typescale.mjs` (lihat Skala tipografi).
4. **Atur detail**: line-height, letter-spacing, lebar baris.
5. **Muat font secara efisien** (subset, woff2, preload).

## Memasangkan typeface

- Kontras yang jelas: display ekspresif + body netral. Jangan dua font yang "mirip tapi beda".
- Satu keluarga variable font bisa cukup untuk display dan body jika punya rentang berat/lebar luas.
- Maksimal 3 keluarga per situs.
- Cek dukungan karakter (huruf Indonesia aman di Latin standar; cek tanda kutip, —, €, Rp).

## Rekomendasi per gaya

Pilihan font gratis dan perlakuannya untuk tiap gaya ada di skill **`web-styles`** (bagian "Tipografi" di pack yang dipilih). Font berbayar/indie yang sering dipakai pemenang Awwwards (cek lisensi web): PP Neue Montreal, PP Editorial New, Neue Haas Grotesk, Monument Extended, Druk. Sumber gratis berkualitas: Google Fonts, Fontshare, Velvetyne, Collletttivo.

Hindari sebagai default: Inter, Roboto, Poppins, Montserrat, Space Grotesk (terlalu umum). Pakai jika user memintanya.

## Skala tipografi (modular scale)

Skala **tidak boleh ditebak**. Semua ukuran dihitung dari satu rumus: ukuran body dikali rasio pangkat n, lalu dibuat fluid antara viewport 360px dan 1440px.

### 1. Pilih rasio
| Rasio | Nama | Karakter | Cocok untuk |
|---|---|---|---|
| 1.067 | Minor Second | sangat rapat | dasbor, UI padat |
| 1.125 | Major Second | rapat | aplikasi, dark-tech |
| 1.200 | Minor Third | seimbang | situs korporat, mobile umumnya |
| 1.250 | Major Third | jelas | situs pemasaran, editorial |
| 1.333 | Perfect Fourth | kontras | editorial, landing page |
| 1.414 | Augmented Fourth | dramatis | luxury, portofolio |
| 1.500 | Perfect Fifth | sangat dramatis | brutalism, hero besar |
| 1.618 | Golden Ratio | ekstrem | poster, hanya untuk sedikit langkah |

Pilih **dua rasio**: satu untuk mobile (360px) dan satu untuk desktop (1440px). Rasio mobile selalu sama atau lebih kecil, karena layar sempit tidak muat lompatan besar. Rekomendasi per gaya ada di bagian "Tipografi" setiap style pack (`web-styles`).

### 2. Hitung dengan generator (wajib)
```bash
node skills/web-typeface/typescale.mjs --ratio-min minor-third --ratio-max major-third \
  --base-min 16 --base-max 18 --mega 112 --hero-chars 24
```
Tanpa akses terminal (misalnya Google AI Studio): minta owner menjalankan perintah ini dan menempelkan hasilnya, atau hitung manual dengan rumus di bawah dan tandai "BELUM DIVERIFIKASI".

Generator menghasilkan blok `@theme` lengkap, tabel min/max px, dan peringatan. Salin hasilnya ke `global.css`. **Jangan mengetik angka clamp sendiri.** Bila ada PERINGATAN, perbaiki rasio atau batasnya, lalu jalankan ulang.

Rumus yang dipakai (untuk dicek manual):
```
min_n  = base_min × rasio_mobile^n        max_n = base_max × rasio_desktop^n
slope  = (max_n − min_n) / (1440 − 360)   intercept = min_n − slope × 360
--text-<n>: clamp(min_n/16 rem, intercept/16 rem + slope×100 vw, max_n/16 rem)
```

### 3. Langkah skala (10 langkah, nama tetap)
| Token | n | line-height | letter-spacing |
|---|---|---|---|
| `xs` | −2 | 1.5 | +0.01em |
| `sm` | −1 | 1.5 | 0 |
| `base` | 0 | 1.6 | 0 |
| `lg` | 1 | 1.5 | −0.005em |
| `xl` | 2 | 1.3 | −0.01em |
| `2xl` | 3 | 1.2 | −0.015em |
| `3xl` | 4 | 1.1 | −0.02em |
| `4xl` | 5 | 1.05 | −0.025em |
| `display` | 6 | 1.0 | −0.03em |
| `mega` | 7 | 0.92 | −0.035em |

Setiap langkah punya pasangan token Tailwind v4: `--text-xl--line-height` dan `--text-xl--letter-spacing`. Dengan begitu, `text-xl` otomatis membawa line-height dan tracking-nya sendiri. `--text-wordmark` (logo/wordmark raksasa, dekoratif) ditambahkan manual dan wajib `aria-hidden="true"`.

### 3b. Menimpa line-height / letter-spacing
Pasangan line-height dan letter-spacing dari generator adalah default. Bila style pack atau design-direction meminta nilai lain (misalnya brutalism `mega` line-height 0.85, luxury body line-height 1.7), design-system **menimpa token**-nya tepat di bawah output generator, misalnya `--text-mega--line-height: 0.85;`, lalu mencatatnya di `docs/design-system.md`. Menimpa lewat `leading-[..]`/`tracking-[..]` di markup tetap dilarang. Ukuran body di pack (misalnya "18–20px") diterjemahkan menjadi `--base-min/--base-max` generator.

### 4. Peran (role) → token
Halaman tidak memakai `text-*` langsung untuk teks berperan. design-system membuat utility peran:
```css
@utility type-h1 { font-size: var(--text-display); line-height: var(--text-display--line-height); letter-spacing: var(--text-display--letter-spacing); font-family: var(--font-display); font-weight: 600; }
```
Tabel peran default (boleh diubah di design-direction, tapi harus ditulis):
| Peran | Token | Catatan |
|---|---|---|
| `type-hero` | `mega` | hanya h1 di hero |
| `type-h1` | `display` | h1 halaman selain hero |
| `type-h2` | `3xl` | judul section |
| `type-h3` | `xl` | judul kartu / sub-section |
| `type-h4` | `lg` | judul kecil, semi-bold |
| `type-lead` | `lg` | paragraf pembuka |
| `type-body` | `base` | paragraf |
| `type-small` | `sm` | teks pendukung |
| `type-caption` | `sm` | keterangan gambar, `--color-muted` |
| `type-label` | `xs` | uppercase, +0.08em, `--font-mono` bila pack memakai font utility (bila tidak, font body) |
| `type-stat` | `2xl` | angka besar, `tabular-nums` |
| `type-quote` | `2xl` | kutipan/testimoni |

### 5. Aturan
- **Zoom (WCAG 1.4.4)**: nilai tengah clamp wajib `rem + vw`, tidak boleh `vw` saja. Maks ≤ 2,5 × min untuk semua teks yang dibaca (generator membatasi otomatis). Wordmark dekoratif (`aria-hidden`) dikecualikan.
- **Batas bawah**: body ≥ 16px; `sm` ≥ 14px; `xs` (label) ≥ 12px.
- **Muat di 360px**: judul hero dicek dengan `--hero-chars` = jumlah karakter **kata atau frasa terpanjang yang tidak boleh terpotong** di mobile (bukan seluruh kalimat; baris boleh pecah antar kata). Bila tidak muat, pendekkan judul atau turunkan `--mega`.
- **Tanpa nilai sembarang**: tidak boleh `text-[..]`, `leading-[..]`, atau `tracking-[..]` di markup. Kebutuhan baru ditambahkan sebagai token atau peran oleh design-system.
- **Hierarki terlihat**: dua peran berurutan (misalnya h2 dan h3) minimal berbeda dua langkah skala, atau satu langkah ditambah perbedaan berat huruf.
- Maksimal 3 berat huruf per situs (misalnya 400, 600, 700).
- **Line-height < 1 dan highlight**: line-height di bawah 1 (default `mega` 0,92) hanya aman bila judul tidak memakai blok latar. Judul dengan highlight (`.mark`) yang bisa membungkus di mobile: override `--text-mega--line-height` ke ≥ 1, dan letakkan blok di bawah teks (`.mark { position: relative; z-index: -1 }` + `isolate` di parent) agar tidak menutup descender baris atas. Cek di 360px.
- Aturan dasar `h1`–`h4` di `@layer base` hanya mengatur `font-family` dan `font-weight`, **bukan** ukuran, line-height, atau letter-spacing; semua itu datang dari peran `type-*`. Ini mencegah aturan dasar bertabrakan dengan peran.

## Detail yang membedakan

- **Line-height** dan **letter-spacing** sudah ikut token tiap langkah (lihat tabel langkah). Label uppercase memakai peran `type-label` (+0.08em).
- **Lebar baris**: body 55–70 karakter (`max-width: 65ch`).
- `text-wrap: balance` untuk judul, `text-wrap: pretty` untuk paragraf.
- `font-variant-numeric: tabular-nums` untuk angka yang berjajar (harga, statistik, tanggal).
- Gunakan tanda baca yang benar: “kutip”, — em dash, – rentang angka.

## Tipografi ekspresif

- Teks raksasa yang terpotong tepi layar (brutalism).
- Campur berat/lebar dalam satu judul (variable font: `font-variation-settings: 'wght' 900, 'wdth' 125`).
- Teks sebagai gambar: outline (`-webkit-text-stroke`), mask gambar ke dalam huruf (`background-clip: text`).
- Teks bergerak diatur oleh skill `web-motion` (SplitText, marquee, animasi variable axis).

## Memuat font di Astro (ringan)

1. Self-host file **woff2** di `public/fonts/` (atau paket `@fontsource-variable/*`).
2. Subset ke Latin (alat: `glyphhanger` atau `pyftsubset`). Target < 50 KB per file.
3. Preload hanya font display hero:
```html
<link rel="preload" href="/fonts/display.woff2" as="font" type="font/woff2" crossorigin>
```
4. `@font-face` dengan `font-display: swap` dan fallback yang ukurannya mirip (`size-adjust`, `ascent-override`) untuk mencegah layout shift.
5. Panggil `ScrollTrigger.refresh()` setelah `document.fonts.ready`.

## Output yang diserahkan

1. Satu kalimat konsep tipografi.
2. Pasangan font + alasan singkat + lisensi.
3. Token `--font-display`, `--font-body`, `--font-mono`, rasio mobile/desktop yang dipilih, dan output generator `--text-*` (dengan pasangan line-height dan letter-spacing).
4. `@font-face` siap pakai dan baris preload.
5. Tabel peran → token (`type-*`) dan utility `@utility type-*`.

# Web Colorist — Ahli Warna

Skill ini menentukan PALET dan cara warna dipakai. Hasil akhirnya selalu berupa token CSS di `src/styles/tokens.css` yang dipakai Tailwind.

## Langkah kerja

1. **Cari asal warna dari subjek**, bukan dari tren. Tanyakan: material apa, tempat apa, budaya apa yang dekat dengan brand ini? (contoh: software house di Jakarta → beton, lampu jalan natrium, layar terminal, batik modern).
2. **Tentukan 1 warna aksen** yang menjadi identitas. Hanya satu.
3. **Bangun netral** dengan sedikit hue dari aksen (bukan abu-abu murni).
4. **Tetapkan peran**, bukan nama warna.
5. **Cek kontras** semua pasangan teks/latar.
6. **Buat versi gelap** dengan sengaja, bukan sekadar membalik.

## Gunakan OKLCH

OKLCH membuat terang-gelap konsisten antar hue. Format: `oklch(L C H)`.
- L (lightness) 0–1: atur hierarki terang/gelap di sini.
- C (chroma) 0–0.37: kejenuhan. Netral 0.005–0.02, aksen 0.15–0.25.
- H (hue) 0–360.

Skala netral: pertahankan H dan C kecil, ubah L saja (contoh L: 0.98, 0.94, 0.86, 0.70, 0.50, 0.35, 0.22, 0.14).

## Token peran (wajib)

```css
:root {
  --bg: ...;          /* latar utama */
  --surface: ...;     /* kartu, panel */
  --fg: ...;          /* teks utama */
  --muted: ...;       /* teks sekunder */
  --line: ...;        /* border, garis grid */
  --accent: ...;      /* aksen identitas */
  --on-accent: ...;   /* teks di atas aksen */
}
@media (prefers-color-scheme: dark) { :root { /* redefinisi token yang sama */ } }
```
Komponen hanya boleh memakai token ini. Jangan ada hex langsung di komponen.

## Aturan proporsi 60-30-10

60% latar/netral, 30% teks dan elemen sekunder, 10% aksen. Aksen dipakai untuk: CTA utama, satu highlight per section, state aktif. Bukan untuk dekorasi di mana-mana.

## Kontras (WCAG)

- Teks body: minimal **4.5:1**.
- Teks besar (≥ 24px, atau ≥ 19px bold) dan ikon/UI: minimal **3:1**.
- Teks di atas gambar: beri lapisan gelap/terang atau latar solid.
- Jalankan pengecekan dengan script kecil (rumus relative luminance WCAG) sebelum menyerahkan palet.

## Palet per gaya

Rentang lightness, chroma, jumlah aksen, dan proporsi warna untuk tiap gaya ada di skill **`web-styles`** (bagian "Warna" di pack yang dipilih). Langkah kerja di atas tetap berlaku untuk semua gaya: aksen dicari dari subjek, netral diberi hue, kontras dicek.

## Warna per section

Section boleh punya mood sendiri lewat atribut `data-mood="<nama>"`. Setiap mood adalah selector CSS `[data-mood="<nama>"]` yang mendefinisikan ulang token warna untuk light DAN dark, jadi dark mode tetap benar. Skill `web-motion` hanya mengganti atribut ini. Maksimal 3 mood dalam satu halaman, semuanya diambil dari palet yang sama.

## Hindari (klise desain AI)

- Krem hangat + serif + aksen terakota.
- Hitam pekat + satu hijau neon / oranye menyala tanpa alasan.
- Gradien ungu-ke-biru di atas putih.
- Abu-abu murni tanpa hue.
Jika user meminta salah satu ini secara eksplisit, ikuti user.

## Output yang diserahkan

1. Satu kalimat konsep warna (asal-usulnya dari subjek).
2. `tokens.css` lengkap light + dark.
3. Tabel kontras pasangan utama (fg/bg, muted/bg, on-accent/accent).
4. Contoh pemakaian di Tailwind (`bg-[var(--bg)]` atau `theme.extend.colors`).
