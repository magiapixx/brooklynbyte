# Peran: Asset Designer

Kamu membuat semua aset visual website: ilustrasi SVG, ikon, diagram,
aset 3D, gambar raster, dan OG image. Kamu bekerja dari **Daftar aset** di
`docs/design-direction.md`. Kamu tidak membuat halaman, tidak membuat
token, dan **tidak menganimasikan**. Aset yang akan bergerak kamu siapkan
strukturnya, lalu `motion-developer` yang menggerakkannya.

## Skill yang wajib dibaca
- Bagian Gaya di design-direction; bila memakai style pack, baca juga bagian
  "Aset" di `skills/web-styles/styles/<pack>.md`
- `skills/web-asset/SKILL.md` untuk teknik, format, optimasi, dan batas ukuran
- `skills/web-colorist/SKILL.md` agar warna aset memakai token
- `skills/web-layout/SKILL.md` agar proporsi aset cocok dengan grid

Kalau isi skill bertentangan dengan `AGENTS.md`, ikuti `AGENTS.md`.

## Yang kamu buat
| Jenis | Lokasi | Format |
|---|---|---|
| Ilustrasi, diagram, ikon (bisa ganti tema) | `src/components/art/<Nama>.astro` | SVG inline, warna dari token |
| Gambar raster (foto, tekstur) | `src/assets/images/` | sumber resolusi penuh; Astro `<Image>` membuat AVIF/WebP |
| Aset 3D prosedural | `src/assets/3d/<nama>.ts` | fungsi murni yang mengembalikan data geometri (tanpa renderer) |
| Model 3D file | `public/models/` | `.glb` terkompresi Draco/Meshopt |
| OG image, favicon | `public/` | PNG 1200×630 untuk OG, SVG untuk favicon |
| Manifest | `docs/assets.md` | tabel semua aset |

Alt text **tidak** kamu tulis. Alt text milik `seo-content` di
`docs/content.md`, dirujuk dengan ID aset. Kamu memakainya sebagai props
atau `<title>` SVG.

## Siap animasi
Untuk aset yang di design-direction ditandai bergerak:
- Beri setiap bagian yang bergerak `data-part="<nama>"` dan kelompokkan
  dengan `<g>` sesuai urutan gerak (misalnya `beam-1`, `beam-2`, `bolt`).
- Garis yang akan "tergambar" memakai `stroke` (bukan `fill`),
  `fill="none"`, dan `vector-effect="non-scaling-stroke"`.
- Aset 3D mengekspor parameter yang bisa dianimasikan (misalnya jumlah
  segmen, titik pusat), bukan objek renderer.
- Tulis di manifest bagian apa saja yang bisa digerakkan.

## Manifest `docs/assets.md`
`| ID | Jenis | File | Dimensi / rasio | Ukuran (gzip) | Bergerak? | Sumber & lisensi |`
- Sumber: "dibuat tim", nama stok + lisensinya, atau "AI: <tool>".
- Aset dari generator AI wajib ditandai dan disetujui owner sebelum rilis.

## Aturan
1. **Tanpa video.** Gerak dibuat dengan SVG + GSAP atau 3D.
2. Warna SVG hanya dari token: `var(--color-*)` atau `currentColor`.
   Tidak ada hex atau `oklch()` langsung, supaya tema gelap dan mood tetap
   benar.
3. Batas ukuran (dicek `qa-reviewer`):
   - SVG inline ≤ 15 KB per aset; SVG eksternal ≤ 50 KB
   - Raster ≤ 200 KB per gambar setelah konversi; total di atas lipatan ≤ 300 KB
   - Model `.glb` ≤ 1 MB, ≤ 50.000 segitiga, tekstur ≤ 1024 px
   - OG PNG ≤ 300 KB
4. Setiap aset 3D atau aset berat wajib punya **fallback SVG statis** yang
   menggambarkan objek yang sama.
5. Jangan membuat logo, foto, atau wajah yang meniru merek atau orang
   nyata. Untuk proyek dengan data fiktif, aset harus jelas fiktif.
6. Jangan menambah dependency tanpa alasan. Alat yang disarankan
   (devDependency): `svgo`, `sharp`, `@gltf-transform/cli`.
7. Aset dekoratif tanpa makna diberi `aria-hidden="true"`. Aset bermakna
   memakai alt text dari `docs/content.md`.

## Di laporan
Daftar ID aset yang dibuat, ukuran tiap aset, bagian yang bisa
dianimasikan (`data-part`), dan aset yang masih menunggu (misalnya foto
dari klien).

# Web Asset — Ahli Aset Visual

Skill ini mengatur cara membuat ASET: ilustrasi, diagram, ikon, 3D, dan gambar. Animasinya diatur skill `web-motion`; warnanya dari `web-colorist`.

## Prinsip

1. **Aset menjelaskan subjek.** Gambar harus menunjukkan sesuatu yang nyata dari dunia klien (produknya, prosesnya, materialnya), bukan bentuk dekoratif acak.
2. **Satu bahasa visual.** Semua aset dalam satu situs memakai gaya garis, sudut, dan palet yang sama.
3. **Ringan dulu.** Pilih format terkecil yang cukup: SVG > 3D prosedural > raster > model `.glb`. Tanpa video.
4. **Bisa ganti tema.** Warna dari token CSS, bukan nilai tetap.
5. **Siap digerakkan.** Struktur aset dirancang untuk animasi sejak awal.

## Memilih format

| Kebutuhan | Format |
|---|---|
| Ilustrasi teknis, diagram, ikon, pola | SVG inline (komponen `.astro`) |
| Objek 3D sederhana (balok, pelat, kemasan, rangka) | Geometri prosedural Three.js |
| Objek 3D kompleks (produk asli, karakter) | `.glb` dari Blender, dikompres |
| Foto produk, tim, lokasi | Raster dari klien atau stok berlisensi |
| Tekstur (beton, kertas, kain) | Shader noise, atau raster ≤ 1024 px yang bisa diulang |
| OG image | PNG 1200×630 |

## Gaya ilustrasi yang tidak terlihat seperti clip-art

Gaya aset (ilustrasi, foto, 3D, ikon) ditentukan bagian "Aset" di style pack (`web-styles`). Teknik di bawah adalah contoh untuk gaya teknis/minimal; gaya lain (misalnya `playful-3d`, `luxury`) memakai perlakuan berbeda.


- **Gambar teknik**: garis tipis seragam (1–1.5 px, `vector-effect="non-scaling-stroke"`), garis ukur, label mono kecil, nomor bagian (`A`, `B`, `01`).
- **Isometrik**: proyeksi 30°. Tiga sisi kotak memakai tiga tingkat terang dari token (`--color-bg`, `--color-surface`, `--color-border`) dengan garis `--color-fg`. Aksen hanya pada satu elemen.
- **Blueprint/diagram**: grid tipis di belakang, elemen utama tegas di depan, panah dan anotasi.
- Hindari: gradien pelangi, bayangan lembut, karakter kartun generik, ikon set bawaan tanpa disesuaikan.

### Rumus isometrik (untuk script pembuat SVG)
Titik 3D `(x, y, z)` ke 2D:
```
sx = (x - y) * cos(30°)
sy = (x + y) * sin(30°) - z
```
Gambar sisi dari yang paling jauh ke paling dekat (urutkan berdasarkan `x + y + z`).
Untuk aset berulang (tumpukan kontainer, rak, rangka), buat script kecil (Python atau Node) yang menghasilkan SVG, lalu simpan hasilnya sebagai komponen. Jangan menulis ratusan path dengan tangan.

## SVG siap animasi

```astro
<svg viewBox="0 0 400 300" role="img" aria-labelledby="t-truss">
  <title id="t-truss">{alt}</title>
  <g data-part="grid" stroke="var(--color-border)">…</g>
  <g data-part="beam-1" fill="none" stroke="var(--color-fg)" vector-effect="non-scaling-stroke">…</g>
  <g data-part="accent" fill="var(--color-accent)">…</g>
</svg>
```
- `data-part` per kelompok gerak, urut sesuai koreografi.
- Garis yang akan tergambar: `stroke`, `fill="none"`, path utuh (bukan banyak potongan kecil). **Jangan** beri `vector-effect: non-scaling-stroke` pada garis yang dianimasikan dengan `drawSVG`; panjang dash jadi salah dan garis tidak tergambar penuh. Pakai `non-scaling-stroke` hanya untuk ilustrasi statis.
- Label teks: hitung lebarnya saat menentukan `viewBox` (perkiraan mono 9px ≈ 6 px per karakter), atau label akan terpotong di tepi.
- Bentuk yang akan muncul/merakit: kelompok `<g>` terpisah dengan `transform-box: fill-box` agar bisa diskalakan dari pusatnya.

## 3D prosedural (Three.js)

Aset 3D adalah **data**, bukan scene. Contoh balok I (profil WF):
```ts
// src/assets/3d/i-beam.ts — tanpa import three; motion-developer yang membuat mesh.
export const iBeamProfile = (h = 1, b = 0.6, tw = 0.08, tf = 0.12) => [
  [-b/2, -h/2], [b/2, -h/2], [b/2, -h/2 + tf], [tw/2, -h/2 + tf],
  [tw/2, h/2 - tf], [b/2, h/2 - tf], [b/2, h/2], [-b/2, h/2],
  [-b/2, h/2 - tf], [-tw/2, h/2 - tf], [-tw/2, -h/2 + tf], [-b/2, -h/2 + tf],
];
```
`motion-developer` memakai profil ini dengan `THREE.Shape` + `ExtrudeGeometry`.
- Batas: ≤ 50.000 segitiga per scene, material sederhana (`MeshStandardMaterial`), maksimal 2 lampu.
- Warna material dibaca dari token saat runtime, bukan ditulis tetap.
- Selalu sediakan fallback SVG yang menggambarkan objek yang sama.

## Raster

- Simpan sumber resolusi penuh di `src/assets/images/`; tampilkan dengan `<Image>` / `<Picture>` dari `astro:assets` (AVIF + WebP, `widths` sesuai layout).
- Foto: ≤ 200 KB per gambar setelah konversi. Hero di atas lipatan: `loading="eager"`, `fetchpriority="high"`; lainnya lazy.
- Konversi manual: `sharp` (`npx sharp-cli` atau script Node).

## Model `.glb`

```bash
npx @gltf-transform/cli optimize in.glb out.glb --compress draco --texture-compress webp --texture-size 1024
```
Decoder Draco di-self-host di `public/draco/` (lihat aturan motion-developer).

## OG image

PNG 1200×630, ≤ 300 KB. Isi: nama brand, satu kalimat, satu elemen visual khas. Hasilkan dari SVG dengan `sharp`:
```bash
node -e "require('sharp')('og.svg').png().toFile('public/og-default.png')"
```

## Optimasi SVG

```bash
npx svgo --multipass -i in.svg -o out.svg
```
Jangan biarkan svgo menghapus `data-part`, `<title>`, atau `vector-effect` (gunakan konfigurasi `removeUnknownsAndDefaults: false` bila perlu).

- [ ] Aset bergerak punya `data-part` dan fallback statis
- [ ] Alt text dirujuk dari `docs/content.md`
- [ ] Sumber dan lisensi tercatat; aset AI ditandai

# Web Colorist — Ahli Warna

Skill ini menentukan PALET dan cara warna dipakai. Hasil akhirnya selalu berupa token CSS di `src/styles/tokens.css` yang dipakai Tailwind.

## Langkah kerja

1. **Cari asal warna dari subjek**, bukan dari tren. Tanyakan: material apa, tempat apa, budaya apa yang dekat dengan brand ini? (contoh: software house di Jakarta → beton, lampu jalan natrium, layar terminal, batik modern).
2. **Tentukan 1 warna aksen** yang menjadi identitas. Hanya satu.
3. **Bangun netral** dengan sedikit hue dari aksen (bukan abu-abu murni).
4. **Tetapkan peran**, bukan nama warna.
5. **Cek kontras** semua pasangan teks/latar.
6. **Buat versi gelap** dengan sengaja, bukan sekadar membalik.

## Gunakan OKLCH

OKLCH membuat terang-gelap konsisten antar hue. Format: `oklch(L C H)`.
- L (lightness) 0–1: atur hierarki terang/gelap di sini.
- C (chroma) 0–0.37: kejenuhan. Netral 0.005–0.02, aksen 0.15–0.25.
- H (hue) 0–360.

Skala netral: pertahankan H dan C kecil, ubah L saja (contoh L: 0.98, 0.94, 0.86, 0.70, 0.50, 0.35, 0.22, 0.14).

## Token peran (wajib)

```css
:root {
  --bg: ...;          /* latar utama */
  --surface: ...;     /* kartu, panel */
  --fg: ...;          /* teks utama */
  --muted: ...;       /* teks sekunder */
  --line: ...;        /* border, garis grid */
  --accent: ...;      /* aksen identitas */
  --on-accent: ...;   /* teks di atas aksen */
}
@media (prefers-color-scheme: dark) { :root { /* redefinisi token yang sama */ } }
```
Komponen hanya boleh memakai token ini. Jangan ada hex langsung di komponen.

## Aturan proporsi 60-30-10

60% latar/netral, 30% teks dan elemen sekunder, 10% aksen. Aksen dipakai untuk: CTA utama, satu highlight per section, state aktif. Bukan untuk dekorasi di mana-mana.

## Kontras (WCAG)

- Teks body: minimal **4.5:1**.
- Teks besar (≥ 24px, atau ≥ 19px bold) dan ikon/UI: minimal **3:1**.
- Teks di atas gambar: beri lapisan gelap/terang atau latar solid.
- Jalankan pengecekan dengan script kecil (rumus relative luminance WCAG) sebelum menyerahkan palet.

## Palet per gaya

Rentang lightness, chroma, jumlah aksen, dan proporsi warna untuk tiap gaya ada di skill **`web-styles`** (bagian "Warna" di pack yang dipilih). Langkah kerja di atas tetap berlaku untuk semua gaya: aksen dicari dari subjek, netral diberi hue, kontras dicek.

## Warna per section

Section boleh punya mood sendiri lewat atribut `data-mood="<nama>"`. Setiap mood adalah selector CSS `[data-mood="<nama>"]` yang mendefinisikan ulang token warna untuk light DAN dark, jadi dark mode tetap benar. Skill `web-motion` hanya mengganti atribut ini. Maksimal 3 mood dalam satu halaman, semuanya diambil dari palet yang sama.

## Hindari (klise desain AI)

- Krem hangat + serif + aksen terakota.
- Hitam pekat + satu hijau neon / oranye menyala tanpa alasan.
- Gradien ungu-ke-biru di atas putih.
- Abu-abu murni tanpa hue.
Jika user meminta salah satu ini secara eksplisit, ikuti user.

## Output yang diserahkan

1. Satu kalimat konsep warna (asal-usulnya dari subjek).
2. `tokens.css` lengkap light + dark.
3. Tabel kontras pasangan utama (fg/bg, muted/bg, on-accent/accent).
4. Contoh pemakaian di Tailwind (`bg-[var(--bg)]` atau `theme.extend.colors`).

# Web Layout — Ahli Tata Letak

Skill ini menentukan STRUKTUR halaman: grid, urutan section, ritme spasi, dan perilaku responsif. Warna diurus skill `web-colorist`, huruf oleh `web-typeface`, gerakan oleh `web-motion`. Jika skill itu tersedia, pakai bersama.

Stack default: **Astro + Tailwind CSS + GSAP + Lenis**. Tanpa video (terlalu berat). Efek visual berasal dari tipografi, SVG, shader/WebGL ringan, dan animasi scroll.

## Langkah kerja

1. **Pahami brief**: apa produknya, siapa audiensnya, apa SATU aksi utama halaman (hubungi, daftar, beli, lihat portofolio).
2. **Pakai style pack** dari `docs/design-direction.md` (skill `web-styles`). Jika belum ada, tanyakan; jangan memilih gaya sendiri.
3. **Tulis peta section** sebelum kode: nama section, tujuan, isi, dan elemen "wow" (maksimal 1 elemen wow per 2–3 section).
4. **Bangun grid dan token spasi** dulu, baru isi section satu per satu.
5. **Cek di 375px, 768px, 1440px**. Halaman tidak boleh scroll horizontal.

## Sistem grid

- Desktop: 12 kolom, gutter `clamp(16px, 2vw, 32px)`, margin luar `clamp(16px, 4vw, 64px)`.
- Tablet: 8 kolom. Mobile: 4 kolom.
- Konten bacaan maksimal ~65 karakter per baris (`max-w-prose`). Lebar baris lain dibuat token oleh design-system (misalnya `--container-measure-narrow: 45ch` → `max-w-measure-narrow`), bukan `max-w-[..ch]`.
- Boleh MELANGGAR grid secara sengaja (elemen menembus margin, teks overlap gambar), tapi hanya di 1–2 titik agar terasa disengaja.

## Token spasi (skala vertikal)

Gunakan satu skala dan patuhi: `4, 8, 12, 16, 24, 32, 48, 64, 96, 128, 192`. Jarak antar section memakai `clamp(96px, 15vw, 192px)`. Atur jarak antar elemen dengan `gap` di flex/grid, bukan margin per elemen.

## Pola section (pilih, jangan pakai semua)

| Pola | Kapan dipakai |
|---|---|
| Hero tipografi raksasa | Brand kuat, pesan pendek |
| Hero split (teks + objek 3D/shader) | Produk teknologi |
| Marquee teks berjalan | Pemisah antar section, daftar klien |
| Section di-pin + konten berganti | Menjelaskan proses langkah demi langkah |
| Scroll horizontal | Portofolio / galeri proyek |
| Kartu bertumpuk (stacking cards) | Layanan atau fitur |
| Grid asimetris (bento tidak simetris) | Showcase campuran |
| Daftar besar dengan hover reveal gambar | Daftar proyek / layanan |
| Footer raksasa (CTA + nama brand full-width) | Penutup |

## Anatomi footer

Footer adalah section penutup, bukan sisa halaman. Rancang dengan wireframe seperti section lain.

**Isi wajib**
- Ulang aksi utama: CTA atau kontak singkat (email sebagai tautan).
- Navigasi: tautan ke section/halaman utama (sama dengan header).
- Tautan sosial sebagai `<a>` sungguhan (atau `[PLACEHOLDER: url]`), bukan teks biasa.
- Info legal: hak cipta, kredit aset, tautan kebijakan bila ada.
- Tombol "kembali ke atas" (tautan ke `#top`).

**Wordmark raksasa** (bila dipakai)
- Lebarnya mengisi kontainer (±95–100%), tidak berhenti di tengah. Ukuran dihitung dari jumlah karakter: `font-size ≈ lebar kontainer / (karakter × lebar huruf)`; buat token `--text-wordmark` dengan nilai `vw` yang sudah dikalibrasi, lalu cek di 360, 1280, dan 1920px.
- Wordmark dekoratif diberi `aria-hidden="true"` dan tidak menggantikan teks brand yang terbaca.

**Struktur dan jarak**
- Kolom informasi mengikuti grid (misalnya 3–4 kolom di desktop, 1–2 di mobile), dengan label kecil di atas tiap kolom.
- Jarak dari section sebelumnya dan antar blok di footer memakai token spasi; tidak ada ruang kosong lebih tinggi dari jarak antar section.
- Footer punya gerak masuk (misalnya wordmark naik dari mask) dan state hover untuk setiap tautan.

## Gaya

Aturan gaya (grid terlihat atau tersembunyi, kerapatan, radius, pola section khas) ada di skill **`web-styles`**, satu file per gaya. Skill ini hanya berisi teknik layout yang berlaku untuk semua gaya. Ikuti pack yang dipilih di `docs/design-direction.md`.

## Struktur file Astro

```
src/
  layouts/Base.astro        # head, font, Lenis + GSAP init
  components/sections/      # Hero.astro, Services.astro, Work.astro, ...
  components/ui/            # Button.astro, Marquee.astro, Cursor.astro
  styles/tokens.css         # warna, font, spasi sebagai CSS variables
  scripts/motion.ts         # semua inisialisasi animasi
```
Satu section = satu komponen. Setiap section punya `data-section="nama"` agar mudah ditarget animasi.

## Aturan wajib

- Halaman lengkap dan terbaca tanpa JavaScript (animasi adalah lapisan tambahan).
- Hero tidak wajib `100vh`; ukur dari isinya.
- Gambar: WebP/AVIF, `loading="lazy"` kecuali hero, selalu ada `width`/`height`.
- Target berat halaman awal < 2 MB.
- Tombol/tautan minimal 44×44px di mobile.
- Gunakan konten nyata, jangan lorem ipsum.

## Checklist sebelum selesai

- [ ] Peta section jelas dan setiap section punya satu tujuan
- [ ] Grid dan spasi konsisten dengan token
- [ ] Tidak ada scroll horizontal di 375px
- [ ] Maksimal satu elemen "wow" per 2–3 section
- [ ] Gaya konsisten dari hero sampai footer
- [ ] Footer memenuhi anatomi footer (isi wajib, wordmark mengisi kontainer, jarak token)
